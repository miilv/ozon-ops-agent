# RUNBOOK — инфраструктура и отладка

> Всё, что нужно свежему агенту/человеку, чтобы понять, где что крутится, и чинить.
> Это **шаблон**: замените `<...>` на свои значения. Конкретные хосты, ключи и адреса
> в публичном репо не хранятся — им место в приватном форке и в `.env`.

## Карта инфраструктуры

```
ЛОКАЛЬНО (машина владельца)            СЕРВЕР (прод)
~/Code/marketplaces              git   VPS Linux · <SERVER_IP> · TZ Europe/Moscow
  ─ разработка, тяжёлые задачи  <───>  /home/ops/marketplaces
  ─ git push/pull = синк         │       ─ все кроны, bridge, датчики
                                 └── GitHub: <you>/<private-repo>
```

- **VPS:** минимум 2–4 GB RAM, 40+ GB диск. Всё, что ниже, влезает без запаса.
- **Доступ:** `ssh ops@<SERVER_IP>` (sudo без пароля) и `ssh root@…` — **только по ключам**,
  парольный вход выключен (`PasswordAuthentication no`). Новому человеку — его pubkey
  в `~/.ssh/authorized_keys` обоих юзеров.
- **Репо на сервере:** `/home/ops/marketplaces`, deploy-ключ GitHub с write.
  Сервер коммитит `state/ docs/` сам; правило: `git pull --rebase` перед push
  (гонки с локальной копией реальны).
- **Секреты:** `/home/ops/marketplaces/.env`, синк с локальной копией по scp — **не через git**.
  Описание переменных: [ENVIRONMENT.md](ENVIRONMENT.md).
- **Авторизация Claude на сервере:** `~/.claude/.credentials.json` (свой OAuth-логин,
  `claude /login` прямо на сервере).
  ⚠️ **Не копировать креды между машинами** — refresh-токены одноразовые, машины
  отзывают друг друга, и вы получите тихий простой агента на несколько суток.
  Trust-флаг для headless: `~/.claude.json → projects["/home/ops/marketplaces"].hasTrustDialogAccepted=true`
  (без него игнорируется allowlist прав из `.claude/settings.json`).

## Сеть

Если сервер стоит в стране, откуда API Anthropic/Telegram/GitHub недоступны напрямую,
исходящий трафик придётся заворачивать в прокси. Конкретный стек — ваше дело; здесь
только грабли, которые ловятся одинаково при любом решении:

- **Заворачивайте оба протокола или выключите IPv6.** Классический тихий отказ:
  прозрачный прокси заворачивает только IPv4, а запрос уходит по IPv6 мимо него с
  локального адреса → 403 от API. Лечение: `net.ipv6.conf.all.disable_ipv6=1` в
  `/etc/sysctl.d/`, либо честная поддержка v6 в прокси.
- **Исключения из редиректа** (иначе останетесь без доступа): приватные сети, свой IP,
  **порт 22 (SSH!)**, uid самого прокси-процесса (иначе его трафик к внешней ноде
  зацикливается), и API, которым нужен локальный IP (например, Ozon и Yandex).
  Исключать по uid, а не по IP ноды, — тогда смена ноды ничего не ломает.
- **Правьте iptables только с dead-man switch:** `systemd-run --on-active=180 …`
  с автооткатом, который отменяете после проверки. Иначе однажды отрежете себе SSH.
- **Проверка:** `curl -s https://api.ipify.org` → должен вернуть внешний IP прокси,
  а не адрес сервера и не пусто.
- **Экстренно снять редирект:** `sudo systemctl stop <transparent-proxy-unit>`
  (SSH выживет, внешние API отвалятся).
- Симптом «провайдер прокси ротировал ключи»: `SSL: UNEXPECTED_EOF` на всех HTTPS
  при живом TCP до ноды. Лечится только свежим конфигом подписки.

## Сервисы и кроны

| Unit | Что | Дебаг |
|---|---|---|
| `tg-bridge.service` | **единственный владелец бот-токена**. Поллит TG, логирует ВСЕ сообщения в SQLite, спавнит сессии `claude -p` (DM/тэг/reply→resume), кнопки, реакция 👍, rich markdown. HTTP API `127.0.0.1:8765`: `/send` `/ask` `/history` | `journalctl -u tg-bridge -f`; `curl -s '127.0.0.1:8765/history?limit=3'` |
| прокси-юниты | см. выше | `systemctl status`, `iptables -t nat -L -n` |

⚠️ **Один бот-токен = один polling-процесс.** Второй поллер (локальный тест, старый
сервис) кладёт бота в `409 Conflict`. Если ставили что-то вроде takopi до своего
bridge — выключите его навсегда, не просто остановите.

Crontab юзера `ops` (`crontab -l`):
```
*/15 * * * *  watchers/orders_watcher.py     # заказы/отмены/дедлайны → TG-алерт (без LLM)
0 8 * * *     claude -p morning-digest       # утренний дайджест в чат
0 14,20 * * * claude -p coo-pulse            # дежурный: NOW+мир → действия/алерты
0 2 * * *     claude -p scribe               # секретарь: транскрипты → журнал, гигиена NOW
0 10 25 * *   claude -p tax-check            # налоговый чек (НДС-дедлайны!)
0 7,19 * * *  watchers/competitor_prices.py  # цены конкурентов (витрина Ozon) → TG на ИЗМЕНЕНИЕ
```
Логи кронов: `~/marketplaces/logs/*.log`.
Транскрипты сессий: `~/.claude/projects/-home-ops-marketplaces/*.jsonl`
(источник истины для ночного секретаря).

**Мониторинг конкурентов:** скрейпер витрины Ozon `tools/ozon_scout.py` (composer-api +
curl_cffi). Дейли-датчик `competitor_prices.py` (`--dry` = без TG) читает
`config/competitors.yaml` — ваши позиции и выверенные под них карточки конкурентов.
Здоровье канала — таблица `scout_health`. 403 на карточку/категорию через API — норма,
надёжно работает только текстовый поиск.

**Обновление списка конкурентов — ручная операция, не крон.** Полная перепись категории
доступна только в залогиненном браузере живого человека (антибот, капча). Авто-матчер по
нескольким страницам выдачи затирал бы выверенный вручную список, поэтому в кроне он
выключен: `scripts/run_matcher.sh` запускается осознанно.

  `postings` (заказы, датчик) · `chat_log` (все сообщения TG; media → `data/chat_media/`) ·

- **Тулзы** (`tools/`): `ozon.py` — generic caller любой ручки Ozon

  лежащем bridge) · `now.py` — правки NOW.md с flock.

## Плейбук отладки: «бот не отвечает»

1. `systemctl status tg-bridge` — упал? `sudo systemctl restart tg-bridge`,
   смотри `journalctl -u tg-bridge -n 50`.
2. В логе `Conflict: terminated by other getUpdates` → **где-то второй polling** —
   найти и убить; у токена может быть только один поллер.
3. `curl -s https://api.ipify.org` пусто / локальный IP → лёг прокси-стек (см. «Сеть»).
4. Bridge жив, но сессии молчат:
   `cd ~/marketplaces && timeout 120 claude -p "ping" < /dev/null`
   — `Not logged in`/401 → перелогин `claude /login` (браузерный флоу, только владелец);
   висит → см. п.3.
5. Сообщение было, реакции 👍 нет → bridge не счёл его триггерным (личка не из whitelist?
   нет тэга/reply?) — смотри `chat_log`:
   `sqlite3 data/store.sqlite "SELECT * FROM chat_log ORDER BY ts DESC LIMIT 5"`.
6. Ответ пришёл plain вместо rich → сработал фолбэк; проверь `sendRichMessage` и лог bridge.

## Плейбук: «сервер недоступен по SSH»

Панель хостинга → перезагрузка. После ребута все юниты `enabled` поднимаются сами;
проверка: `systemctl is-active tg-bridge <proxy-units>` + `curl api.ipify.org`.

## Известные грабли

- **`.env` не в git** — после клона агент не увидит ключей: копировать по scp.
- **Гонка NOW.md**: сервер и локальная копия коммитят оба → всегда `git pull --rebase`;
  NOW править через `tools/now.py` (там flock).
- **Ozon `/v2/finance/realization`** отдаёт 404 за месяцы без продаж — это норма, не ошибка.
- **Бот не может написать в личку первым** — человек должен один раз нажать Start.
- **chat_id группы** хранится с префиксом `-100` (например `-100<TEAM_CHAT_ID>`) — именно
  в таком виде в `.env`.
- **OAuth-токен Claude на сервере умирает молча.** Симптом — агент «просто перестал
  отвечать» на сутки-двое. Проверяйте `claude -p "ping"` в мониторинге, а не по факту тишины.
