# journal/ — дневник

Одна задача или сессия = один файл `YYYY-MM-DD-<slug>.md`, append-only. Не редактируем
задним числом: журнал честно описывает прошлое, в том числе ошибки. Уборки не требует —
в отличие от `state/NOW.md`, который чистится безжалостно.

Зачем: материал для еженедельного ретро, контекст для будущих сессий («мы это уже
пробовали, вот чем кончилось») и аудит действий рядом с детерминированным `action_log`
в SQLite.

Что попадает в запись: что делали, почему так решили, что получилось, чем проверили.
Что **не** попадает: PII покупателей (ФИО, телефоны, адреса) — только номера отправлений.

Образец — [`2026-01-15-example-entry.md`](2026-01-15-example-entry.md).
