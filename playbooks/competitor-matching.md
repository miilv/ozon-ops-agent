# Плейбук: матчинг конкурентов (claude -p)

**Что делает:** сопоставляет карточки конкурентов на Ozon нашим SKU. Автоматика
(ценовой коридор) отсекает аксессуары, но разделять модель/комплектацию —
контекстное решение, поэтому судит LLM. Запускается кроном раз в N дней и вручную
после заведения новых карточек.

**Почему не эвристикой:** в одном ценовом коридоре лежат разные модели (Mavic 4 Pro
рядом с Mavic 3 Classic), разные комплектации (RC / тушка / Fly More Combo) и
отдельные пульты («Пульт DJI RC» — это аксессуар, но слово «пульт» есть и в
названиях дронов с пультом). Только чтение названия в контексте даёт верный матч.

## Шаги

1. **Собрать кандидатов** (детерминированно, сеть):
   ```
   python3 scripts/gather_candidates.py --pages 3
   ```
   → пишет `state/competitor_candidates.json`: по каждому нашему SKU список тайлов
   (sku, name, price, orig_price, stock_left, rating, reviews, url).

2. **Прочитать** `state/competitor_candidates.json`.

3. **Судить каждого кандидата** по правилам ниже. Для каждого нашего SKU собрать
   список подтверждённых конкурентов.

4. **Записать решение** — сформировать JSON вида
   ```json
   {
     "<наш_sku>": [
       {"sku":"<sku конкурента>", "name":"<название>", "config":"RC|body",
        "note":"почему матч", "url":"<url>"},
       ...
     ]
   }
   ```
   и применить:
   ```
   python3 scripts/apply_matches.py <файл_с_решением>.json
   ```
   Скрипт запишет `matched[]` в `config/competitors.yaml`, обновит таблицу
   `competitor_cards`, деактивирует ушедших и напечатает НОВЫХ конкурентов.

5. **Отчитаться:** если появились новые конкуренты — коротко в TG-дайджест
   (`python3 tools/tg.py send "..."`), иначе только запись в журнал. Говори
   результатом, не процессом (правило 7).

## Правила матчинга (строго)

**МАТЧ = та же модель И та же комплектация.**

- **Модель — точно та же.** Разные товары, НЕ матчить между собой:
  Mavic 3 Classic ≠ Mavic 3 Pro ≠ Mavic 3 (обычный) ≠ Mavic 4 Pro ≠
  Neo ≠ Neo 2 ≠ Mini/Mini 4K ≠ Avata ≠ Matrice.
  Версии Cine / Thermal / T / Enterprise (E) — это другие товары, исключать.
- **Комплектация — та же:**
  - `RC` — с пультом с дисплеем: «RC», «DJI RC», «RC 2», «пульт с экраном».
  - `body` — тушка: «тушка», «body», «only drone», «без пульта», «No RC».
  - **Fly More Combo / Creator Combo — это ДРУГАЯ комплектация** (доп. АКБ/пульт),
    НЕ матчить к базовым RC/body. Можно отметить в note как смежный, но не в matched.
  - Пульт с индексом Pro (RC Pro / RC Plus) при нашем обычном RC — другой набор,
    исключать.
- **Отдельные пульты** («Пульт DJI RC», «FPV Remote Controller») — аксессуар,
  исключать всегда.
- **Уценка/б/у/восстановленный** — исключать.
- **Сомнение по модели или комплектации → НЕ матчить** (консервативно). matched[]
  напрямую рулит ценовыми алертами — ложный матч даёт ложную тревогу. Если тайл
  выглядит релевантным, но комплектация неясна из названия — оставь в note,
  не в matched.

## Тюнинг коридоров

Если по нашему SKU почти нет кандидатов или реальные конкуренты вываливаются за
`price_band` (видно по обрезке на краях диапазона) — предложи скорректировать
`price_band` в конфиге и пере-собери. Коридор нужен только чтобы отсечь аксессуары;
делать его у́же смысла нет, шире — лови всё, LLM отфильтрует.
