# MPStats — продажи и цена покупателя по Ozon SKU

Обёртка над `tools/mpstats.py` — клиентом внутреннего API плагина MPStats (зареверсен из Chrome-расширения). Авторизация — кука `MPSTATS_COOKIE` в `.env` (JWT `mp_auth`, живёт ~полгода). Квота плагина 13000, батч из сотен SKU = **1 единица** — можно не экономить.

## Когда что вызывать

**Цена, которую реально платит покупатель (после СПП/Ozon-Карты)** — главное, чего не даёт наш API прайсинга:
```
python3 tools/mpstats.py ozon <sku> --json
```
Читать `pricesGraph` (массив за 30 дней) → последняя ненулевая = текущая витринная цена покупателя. **Только на ОДИНОЧНОМ SKU** — в батче графиков нет, там лишь `price_est = выручка/заказы` (средняя, грубее).

**Кто и сколько продал (30 дней), выручка, тренд, остаток, реклама:**
```
python3 tools/mpstats.py ozon <sku1> <sku2> ...      # таблица; --json для сырья
```
Поля: `Seller/SellerId` (кто продаёт), `Totals.orders`/`Totals.sum` (шт/₽ за 30д), `sumPrev` (тренд), `Count` (остаток), `OrdersPerDay`, `Ext*Advertising` (внешняя реклама).

**Остаток по складам FBO/FBS:** `python3 tools/mpstats.py warehouses <sku>`

**Обход всех наших конкурентов** (из `state/dji_competitors.json`) + снапшот для дайджеста:
```
python3 tools/mpstats.py pull --store       # пишет state/competitors_sales_pulse.md + БД
```

**Проверка доступа/квоты/срока куки:** `python3 tools/mpstats.py whoami`

## Важно

- **Наши собственные продажи в MPStats видны как продажи продавца <STORE>** — можно проверить, отразилась ли наша сделка (по SellerId + скачку orders/revenue за день в графиках).
- `pricesGraph` — это витрина покупателя. Для НАШЕЙ маржи/налогов берём базу ЛК (до СПП) из `/v5/product/info/prices`, НЕ витрину. Разница цен и как считать реальный вычет Ozon — см. `ozon-pnl-model.md` (блок «две цены»).
- Кука протухла → `AuthError` (403). Обновить: mpstats.io ▸ DevTools ▸ Network ▸ запрос `mpstats.io` ▸ Cookie ▸ `mp_auth=...` ▸ в `.env` `MPSTATS_COOKIE='mp_auth=<jwt>'`.
- Как модуль: `from mpstats import fetch_ozon, parse_item, user_info`.
